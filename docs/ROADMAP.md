## После первого релиза

Решение от 23 августа 2026: 1.0 выходит только с русским интерфейсом и русскими
книгами. Правки после первой публикации проходят ревью быстрее и придирок к ним
меньше. Оговорка: новый язык интерфейса — это всё равно новая сборка и новое
ревью; бесплатно добавляются только локализации карточки в App Store.

- **Языки — по одному, интерфейс вместе с языком.** Интерфейса на английском
  не будет: приложение продаётся тем, кто английский учит, а не тем, кто на нём
  говорит. Язык интерфейса совпадает с родным языком читателя, то есть с языком
  книг. Добавляем испанский пакет — вместе с ним появляется испанский интерфейс.

  Стоимость языка определяется одним: есть ли у Apple лемматизатор.
  Проверено `NLTagger.availableTagSchemes(for: .word, language:)`
  на macOS 26.5 — перед выбором языка перепроверить на самом iOS:

  | Лемматизатор Apple | Языки | Чего стоит пакет |
  |---|---|---|
  | Есть | **испанский, португальский, французский, турецкий**, русский | словарь из Викисловаря плюс списки служебных слов — дни |
  | Нет | итальянский, немецкий, польский, японский, корейский, китайский, арабский, хинди, **украинский**, ещё десяток | плюс своя таблица «форма → лемма», десятки мегабайт к словарю — недели |

  Отсюда очередь: следующим разумно брать **испанский или португальский**
  (Бразилия) — большой рынок, охотно платят, лемматизатор бесплатный.
  Украинский попадает в дорогую половину при небольшом рынке; делать его
  стоит по личным причинам, а не по расчёту.

- **Локализация интерфейса — 114 строк, день работы.** SwiftUI локализует
  строковые литералы сам, как только появится каталог строк. Руками надо
  переписать места, где текст лежит в обычной `String` и потому не
  локализуется: ошибки в `PurchaseStore`, названия тем и шрифтов в `Theme`,
  надпись над заголовком в `PaywallView`, ярлыки частей речи и зон кольца
  в `Core`. **Отдельно:** кнопки цены в `SettingsView` и `PaywallView` собраны
  через `store.displayPrice.map { … } ?? …`, то есть дают `String` вместо
  `LocalizedStringKey` — при локализации они молча останутся русскими.
  Сегодня это ни на что не влияет: интерфейс и так русский.

- **Обратное направление: английская книга с русскими или украинскими словами,
  для англоязычных.** Идея от 23 августа 2026. Технически самое дешёвое
  расширение из всех:

  - лемматизатор для английского у Apple есть (`beds → bed`, `got → get`,
    проверено), а морфология целевого языка не нужна вовсе — в английскую
    фразу вставляется словарная форма, и грамматику держит английский:
    «I got up from the кровать». Тот барьер, из-за которого украинский
    в прямом направлении стоил недели, здесь отсутствует;
  - русский и украинский берутся из одного файла: английский Викисловарь
    на kaikki.org хранит таблицы переводов сразу на оба языка;
  - английская классика в общественном достоянии (Гутенберг) вшивается
    в приложение легально — полка не пустая на первом запуске,
    и отпадает риск отказа по Guideline 2.1.

  Нерешённое, и это главное: **кириллица**. Англичанин не может прочитать
  «кровать», пока не выучил алфавит, — подмена превращается в дыры в тексте.
  Вероятный ответ — режим транслитерации (`krovat'`) с переключением
  на кириллицу, когда алфавит освоен. Это надо закладывать в замысел,
  а не пришивать потом.

  Форма: **отдельное приложение** со своим таргетом в этом же репозитории,
  `ReaderCore` переиспользуется как есть. Аудитории не пересекаются —
  другой язык интерфейса, другие ключевые слова, другая цена.

- Множественное число: `яблоками → apples`, а не `apple`
- Падежи для предлогов вместо частотных вариантов
- Синхронизация полки и позиции чтения через CloudKit
- iPad: две колонки, боковая панель
