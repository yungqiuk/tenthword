# Архитектура

## Слои

```
App/Chitalka/          SwiftUI, SwiftData, StoreKit. Знает про Core, Core про него — нет.
      │
Core/ReaderCore/       Чистая логика перевода. Ни SwiftUI, ни UIKit, ни файловой системы.
                       Собирается и тестируется через `swift test` без Xcode.
```

Правило: если код можно проверить тестом без симулятора — он живёт в `Core`.

## Конвейер перевода

```
        текст главы (String)
                │
    ┌───────────▼────────────┐
    │ Tokenizer              │  слова + смещения в UTF-16
    │                        │  (UTF-16, потому что TextKit и NSAttributedString
    │                        │   работают в этих единицах)
    └───────────┬────────────┘
                │ [WordToken]
    ┌───────────▼────────────┐
    │ Lemmatizer             │  кровати → кровать
    │  AppleLemmatizer       │  NLTagger, схема .lemma, офлайн, в бандле не весит
    │  PassthroughLemmatizer │  заглушка для тестов и для не-Apple платформ
    └───────────┬────────────┘
                │
    ┌───────────▼────────────┐
    │ WordDictionary         │  кровать → bed (сущ.)
    │  SQLiteDictionary      │  Data/ru-en.sqlite в бандле приложения
    │  InMemoryDictionary    │  для тестов
    └───────────┬────────────┘
                │ [Candidate]
    ┌───────────▼────────────┐
    │ CandidateRanker        │  фиксированный порядок: что переводить первым
    └───────────┬────────────┘
                │ PreparedText  ← вычисляется один раз на главу, кешируется
    ┌───────────▼────────────┐
    │ .plan(percent:)        │  срез первых N, где N = round(percent/100 × всего слов)
    └───────────┬────────────┘
                │ TranslationPlan
           ReaderView          подменяет слова по смещениям, красит акцентом
```

## Почему порядок фиксирован

`PreparedText` хранит массив кандидатов, отсортированный раз и навсегда.
Процент не участвует в сортировке — он только отрезает префикс.

Из этого бесплатно следует всё, что нужно продукту:

- план на 10% содержит в себе весь план на 5% — текст не перетасовывается под пальцем;
- вернулся на страницу назад — те же слова переведены;
- та же книга на iPhone и iPad выглядит одинаково без синхронизации чего-либо.

Тест `testMonotonicity` проверяет первое свойство перебором всех процентов от 0 до 100.
**Его нельзя ломать.**

## Порядок сортировки

Двухуровневый:

1. **Ярус.** Знаменательные слова (существительные, глаголы, прилагательные, наречия) —
   ярус 0. Служебные — ярус 1, до них дело доходит после ~55%.
2. **Вес внутри яруса.** `0.65 × частотность + 0.35 × StableHash(лемма#порядковый номер)`.

Частотность даёт полезность: частые слова учатся первыми. Хеш даёт разброс по странице,
чтобы переведённые слова не собирались в начале главы. Обе составляющие детерминированы.

Слова, помеченные читателем как выученные, из кандидатов исключаются — их процент
достаётся новым словам.

## Что исключается навсегда

- Числа и слова с цифрами.
- Имена собственные: заглавная буква не в начале предложения.
- Слова, которых нет в словаре.
- Слова, у которых в словаре несколько несвязанных значений (`ambiguous = 1`).
  «Ключ» — key или spring? Без контекста выберем неверно. Теряем ~15% кандидатов,
  зато не врём читателю.

## Единицы измерения

**Смещения — в UTF-16.** Не в `String.Index`, не в байтах. TextKit, `NSRange` и
`NSAttributedString` работают в UTF-16; любое другое представление придётся
конвертировать на каждом кадре прокрутки.

**Страница — 1800 символов**, а не экран. Иначе крупный шрифт даёт читателю втрое
больше «бесплатных страниц» в день. `ReadingUnits.pageCount(forCharacters:)`.

## Кеширование

`PreparedText` строится один раз на главу и живёт, пока глава открыта.
Токенизация + лемматизация главы на 40 тысяч знаков — десятки миллисекунд,
это не в цикле отрисовки, но и не на каждый поворот кольца.
Поворот кольца пересчитывает только `.plan(percent:)` — это срез массива, мгновенно.

## Чего в Core намеренно нет

- Пагинации. Это TextKit 2, он есть только на Apple-платформах и требует симулятора.
- Разбора EPUB. Работа с файлами и ZIP — в `App/Chitalka/Import/`.
- Хранилища. SwiftData живёт в приложении.
